# Consistency audit — 4 November 2026

This audit lists the gaps observed in the local interface and in the code. It is a working inventory, not a certification of every feature. Fixes are ticked after verification. Last reviewed against `CHANGELOG.md` and the pull requests merged up to #75.

## Priority 1 — misleading information or destinations

- [x] **License and welcome**: the License page presents the MIT license and the welcome flow no longer asks for an enterprise key. The historical notices are kept.
- [ ] **Installation and update**: `install.sh` is disabled until its Linux path and its inherited destinations are adapted and validated. The local installation documented in the README uses `scripts/dev-local.sh`; the other paths have not yet been validated for this project. The tools page and the Settings page now say so (#69).
- [x] **Profile and feedback**: the inherited registration form was removed, user feedback opens the issues of this repository, and the original registration service is disabled by default, including for an older configuration.
- [x] **Donations**: the button opens the PayPal link configured by the owner. The recipient was verified on PayPal; the link can be changed or removed in Settings → Support.

## Priority 2 — Claude and Codex

- [x] **Statistics**: the quota shown concerns Claude only. On macOS, the message now distinguishes a sign-in that may go through the keychain from the quota being unreadable.
- [ ] **Usage**: new turns are now broken down by agent; older turns or turns without data stay unattributed. The real prices and quotas of the subscriptions cannot be deduced from a token counter; the available data still has to be examined before showing a Codex cost or quota.
- [x] **Claude amounts**: the amounts shown are marked as indicative and no longer claim to determine billing. Usage credits can lead to extra charges; the real invoice is to be checked with Anthropic. Codex is not included in this amount.
- [ ] **Codex counting**: turns before the fix could count cached tokens twice. New turns separate the categories; historical figures are not recalculated automatically.
- [x] **Connections and settings**: a Codex page shows the status of the CLI and the current limits; the connection was verified on the computer.
- [x] **Agent health**: when Codex is signed in, a missing Claude sign-in is information rather than a general failure; Claude is still needed to use it and for two-agent discussions.
- [x] **Conversation summary**: a session's menu offers a summary, the decisions and actions to select before any task is created. The real test was done with Codex; the cost of this call is not yet included in the statistics.
- [x] **Shared memory**: from the summary, the text can be reread and edited before it is explicitly added to the topic's memory. Codex reads it at its next turn; Claude loads it normally when a new thread starts. Writes refuse symbolic links and a memory too large for Codex.
- [x] **Session connections**: conversations use short requests; compatible tabs share one update connection and take over if it closes. Tested locally with several tabs; browsers without coordination keep one connection per tab.
- [x] **Uneven features**: several pages and hints assume Claude; check for each path whether Codex, the discussion and Telegram are really supported, and state the limits. Progress: companion roles choose their engine and external engines appear in single-agent sessions, with unsupported plan or file features refused clearly (#44); the new session form explains each mode and turns off attachments, with the reason, for modes that take text only (#64). The Claude Code-only features (side questions, MCP servers, scheduled prompts, Claude swarm, context gauge and automatic compactions, Protect the secrets, usage quota, new sessions from Telegram) were checked in the code and are listed in the Sessions guide ("What works with Codex") and in Settings → Codex; Summary and actions needs Codex.
- [ ] **Computer browser**: no agent binary is published in the manifest; its inherited URL points to the original project. The code builds for this Mac and its Go tests pass; real pairing and control remain to be verified before offering its installation.

## Priority 3 — general consistency and documentation

- [x] **System on macOS**: estimated memory, load and uptime are read on the Mac. Unavailable data is no longer shown as zero; the systemd commands and the unvalidated automatic updates are hidden and blocked in local mode.
- [x] **Dashboard**: the server card distinguishes unavailable measurements, the card texts no longer name the agents with the old name, and the Claude quota no longer claims that the account is signed out.
- [x] **Local scheduled tasks**: a scheduler independent of the system crontab runs the tasks while the application is running. Missed runs are skipped unless a job is set to catch up (one run at the next start); `@reboot` jobs run each time the application starts. Scheduled prompts use Claude Code.
- [ ] **Recovery after an interruption on macOS**: if a task process becomes an orphan, its identity cannot yet be checked with the Linux method; it is therefore not stopped automatically, to avoid killing another process.
- [ ] **Inherited internal paths**: some links still use the historical system topic. A migration must preserve existing projects, sessions and extensions.
- [ ] Rework the embedded documentation pages, the inherited texts and links, and the notifications produced by the server, keeping the applicable attributions and licenses. Progress: the server, command line, interface and docs name the `pilot` command and the product harness-pilot, including update and rollback notifications (#33, #36, #37, #40); the tools, Settings and development mock pages match the code (#69); `docs/dev/API.md` lists every registered route, checked by a test (#75).
- [x] **Critical documentation**: the memory, security, Telegram and command pages separate the behaviour verified locally from inherited features not yet validated.
- [x] **Documentation navigation**: links between guides, including Markdown file names and links to a section, work in the application; the licenses and the audit open the repository files.
- [ ] Verify the memory, task, automation and backup features with both agents; preserve existing data.
- [x] **Isolated task and backup tests**: 92 tests pass on macOS with a simulated GitHub; a non-UTF-8 file name test is skipped when the file system forbids it. This does not validate a real backup of the user's account.
- [x] **Restore preview and result**: the latest backup can be previewed even without local history; the reviewed version is frozen and the skipped or held files are shown. An isolated test with a simulated Git repository checks that project metadata, tasks and memory come back and that previous versions are kept.
- [x] **Complete instance backup**: an encrypted local archive includes the state, conversations, attachments, projects, files and labels. Restoring prepares a separate copy in read-only mode, then the owner turns on its services. The tests check authentication, history, an attachment and the activation of the copy. The GitHub memory backup stays selective; no private data was sent to the real GitHub account in this test. Since then: a restored copy keeps Telegram, scheduled jobs and the memory backup paused until the owner resumes them (#48), archives carry a versioned key-derivation header (#51), kept exports can be listed and deleted (#53), decrypted previews expire after one hour (#54), and a Files root set to the home folder is left out instead of blocking the export (#58).
- [x] **Isolated Telegram tests**: 43 format, synchronization and connection tests pass with simulated services; a real connection and discussion with a bot remain to be verified.
- [ ] **Development mock**: `web/mock` answers about half of the API routes (141 of 304 on 4 November, see `docs/dev/DESIGN.md`), so the pages that use the missing routes cannot be checked against it.
- [ ] Verify the screens on computer and mobile, the error states, accessibility and translations. The two-agent discussion form was checked visually at mobile width; a first width check was also made on the statistics, Codex, Telegram, Support and the sessions guide. The other paths remain to be examined. Progress: block numbers and schedule descriptions follow the interface language (#38, #67), the companions error state is translated (#29), form choices wrap on a phone (#25).
