# Consistency audit — 4 November 2026

This audit lists the gaps observed in the local interface and in the code. It is a working inventory, not a certification of every feature. Fixes are ticked after verification. Last reviewed against `CHANGELOG.md` and the pull requests merged up to #167.

## Priority 1 — misleading information or destinations

- [x] **License and welcome**: the License page presents the MIT license and the welcome flow no longer asks for an enterprise key. The historical notices are kept.
- [x] **Installation and update**: `install.sh` installs this repository again on Debian 12 and Ubuntu 24.04 (#87, #117). It was run end to end in arm64 systemd containers: the public download, the Git path, `pilot update` and `install.sh --update`, `pilot doctor`, HTTPS with a test domain behind Caddy, the tools installed in the background, and `pilot uninstall --purge` (#132, #140; `docs/dev/INSTALLER.md`). The README and the Installation guide say what was verified. Not verified yet: x86_64, a real server (firewall and SSH hardening), a Let's Encrypt certificate for a real domain, `ACCESS=tailscale` and `RESTORE_FROM`. The local installation on macOS uses `scripts/dev-local.sh` and is updated with Git; Settings → System says so and `pilot update` refuses to run there (#92).
- [x] **Profile and feedback**: the inherited registration form was removed, user feedback opens the issues of this repository, and the original registration service is disabled by default, including for an older configuration.
- [x] **Destinations of the original project**: the `pilot update` hint, `pilot license status`, the backup skill's move to a new server, `SECURITY.md`, `CODE_OF_CONDUCT.md` and the issue form now point to this repository; the funding, Enterprise and X links are gone. What still names the original project (the computer agent's release URL, the license, registration and feedback service, gated by `MAXXING_LICENSE_PING=1`, a few docstrings and internal names) is never contacted by default and is listed in `docs/dev/INSTALLER.md` ("What pointed to the original project").
- [x] **Donations**: the button opens the PayPal link configured by the owner. The recipient was verified on PayPal; the link can be changed or removed in Settings → Support.

## Priority 2 — Claude and Codex

- [x] **Statistics**: the quota shown concerns Claude only. On macOS, the message now distinguishes a sign-in that may go through the keychain from the quota being unreadable.
- [x] **Usage**: new turns are broken down by agent; older turns or turns without data stay unattributed. Codex turn events carry tokens only, neither a cost nor plan limits: Settings → Stats says so and estimates nothing. The cost shown is Claude Code's own estimate, for Claude only.
- [x] **Claude amounts**: the amounts shown are marked as indicative and no longer claim to determine billing. Usage credits can lead to extra charges; the real invoice is to be checked with Anthropic. Codex is not included in this amount.
- [x] **Codex counting**: turns before the fix counted cached tokens twice. They are recalculated once from each session's log when the statistics are opened, and Settings → Stats says how many.
- [x] **Connections and settings**: a Codex page shows the status of the CLI and the current limits; the connection was verified on the computer.
- [x] **Agent health**: when Codex is signed in, a missing Claude sign-in is information rather than a general failure; Claude is still needed to use it and for two-agent discussions.
- [x] **Conversation summary**: a session's menu offers a summary, the decisions and actions to select before any task is created. The real test was done with Codex; without a signed-in Codex, Claude Code writes it, and the call's tokens (and Claude's indicative amount) now count in the session's statistics.
- [x] **Shared memory**: from the summary, the text can be reread and edited before it is explicitly added to the topic's memory. Codex reads it at its next turn; Claude loads it normally when a new thread starts. Writes refuse symbolic links and a memory too large for Codex.
- [x] **Session connections**: conversations use short requests; compatible tabs share one update connection and take over if it closes. Tested locally with several tabs; browsers without coordination keep one connection per tab.
- [x] **Uneven features**: several pages and hints assume Claude; check for each path whether Codex, the discussion and Telegram are really supported, and state the limits. Progress: companion roles choose their engine and external engines appear in single-agent sessions, with unsupported plan or file features refused clearly (#44); the new session form explains each mode and turns off attachments, with the reason, for modes that take text only (#64). Codex now also gets scheduled prompts (#128), the MCP servers of Settings → MCP, with only their read-only tools outside Full access (#146), Protect the secrets (#166), and new sessions and discussions from Telegram, checked with a simulated Telegram only (#167). The features still for Claude Code only (MCP sign-ins and the claude.ai connectors, Claude swarm and the Agent map, the context gauge and automatic compactions, the extra rules of Claude's permission settings, the usage quota) were checked in the code and are listed in the Sessions guide ("What works with Codex") and, in short, in Settings → Codex; Summary and actions uses Codex, or Claude Code when Codex is not signed in.
- [ ] **Computer browser**: the agent builds reproducibly for the six targets (`pc-agent/build.sh`, #171). On 4 November 2026 it was verified end to end against an isolated test server, with a simulated release and test browsers, on macOS arm64, macOS Intel (Rosetta) and Linux arm64 (container). Download with checksum, pairing, confirmation and refusal, Claude's browser tools, the agent's own refusals, Stop now, idle stop, Erase the profile, reconnection and Disconnect all work; details in `pc-agent/README.md` ("Verified"). Before its installation is offered: publish a first release and fill `server/maxxing/pc_agent.json` (`docs/dev/PC-AGENT.md`). Not verified: Windows, Linux amd64, a visible window of an installed browser, Start with the computer, and a download through a web browser. On macOS that download is not notarized, and on macOS and Linux it is not executable; the terminal command handles both.

## Priority 3 — general consistency and documentation

- [x] **Recovery after an interruption on macOS**: without `/proc`, the identity of an orphaned task process is checked with its start date read by `ps` (in UTC). The next run of the task stops it only when it is still the same process; a process number reused by another program is never killed. Tested for real on this Mac: `tests/test_cron_orphans.py`.
